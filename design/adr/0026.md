# ADR-0026: メトリクスの説明文はドキュメントだけに置き、コードには ID とスコープだけを持つ

- **Status:** Accepted
- **Date:** 2026-09-29
- **Deciders:** lunaInsidious, Claude
- **Tags:** metrics, docs, api

## Context

### Problem

メトリクスの説明文（名前、説明、定義、入力、計算方法、制約、参考文献、単位、言語依存性、日本語訳）を `MetricDefinition` としてコードに持ち、ドキュメントの生成、`srcmetrics metrics` コマンド、`GET /api/metrics` に使っていた（ADR-0023 のメトリクス定義の生成、ADR-0025）。その結果、次の問題が出た。

- 翻訳を加えるたびに、定義を作るヘルパー関数の引数が言語数に比例して増える
- 説明文が公開 API の一部になり、文言の修正や言語の追加が破壊的変更になる（0.1.0 公開後に `ja` フィールドを足したことが既に破壊的変更だった）
- 利用者向けの説明は、コードや API ではなくドキュメントで読めば足りる

## Decision

- コードの登録簿は `MetricSpec { id, scopes }` だけにする。用途は、出力の検査（各スコープで定義どおりの ID が出ること）、CSV の列の順序、統計・モデルの対象の選択
- 説明文はすべて `docs/metrics/`（英語）と `docs/ja/metrics/`（日本語）に手で書く。コードからは生成しない
- `tests/docs.rs` は、コードの全 ID が英語と日本語の両方のメトリクスページに載っていること、ページにコードにない ID が載っていないことだけを検査する
- `srcmetrics metrics` コマンドと `GET /api/metrics` は削除する。解析結果にはすべての ID が入っており、意味はドキュメントで読む
- `DEFINITION_VERSION`（計算方法の版）はコードに残し、結果に記録する
- これらは 0.1.0 に対する破壊的変更なので 0.2.0 として公開する（Cargo の semver では 0.x のマイナー更新で破壊的変更を行う）

この ADR は ADR-0025 を置き換え、ADR-0023 のうち「メトリクス定義をコードから生成する」部分を置き換える。

### Rationale

- 説明文の置き場所をドキュメントに一本化すれば、コード・API・翻訳の三重管理がなくなる
- 機械的に守るべきもの（ID とスコープが出力と一致すること、全 ID が文書化されていること）はテストで守れる

## Alternatives Considered

### 言語ごとの文章を `PerLang<Text>` にまとめ、ヘルパーの引数を固定する
**Pros** 引数の肥大化は解消する
**Cons** 説明文を公開 API に持つこと自体の問題（翻訳・文言修正が API の変更になる、コードが文章で埋まる）は残る
**Rejected because:** 説明文をコードに持つ理由がない

## Consequences

### Negative
- 計算方法を変えたとき、ドキュメントの説明を直し忘れても、テストでは検出できない（ID の有無しか見ない）。AGENTS.md の手順で担保する
