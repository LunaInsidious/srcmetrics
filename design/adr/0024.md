# ADR-0024: 初期要求仕様 PLAN.md を廃止し、設計原則を SPEC.md に移す

- **Status:** Accepted
- **Date:** 2026-09-29
- **Deciders:** lunaInsidious, Claude
- **Tags:** docs, process

## Context

### Problem

PLAN.md は初期の要求仕様と実装の優先順位（Phase 1〜4）だった。Phase 4 まで実装を終え、以後の変更は ADR で管理している。PLAN.md が「唯一の進行指針」のままだと、実装済みの計画と現在の仕様が混在する。

## Decision

- PLAN.md を削除する
- 今も有効な内容は `design/SPEC.md` に移す
  - 目的とスコープ（対象外を含む）
  - 設計原則 P1〜P11（旧 §6, §10, §13〜§17, §19 のうち有効なもの）。コード中の参照は「design principle Pn」とする
- メトリクスの要件（旧 §8, §9）は実装済みで、定義はコード（`docs/metrics/` に生成）が正
- ADR-0001〜0023 に出てくる「PLAN §x」は、決定当時の記録として書き換えない。原文は git 履歴（コミット 5812948 の `PLAN.md`）で参照できる
- AGENTS.md は、開発の進行指針を「SPEC.md の設計原則と ADR」に改める

### Rationale

- 役目を終えた計画を指針として残すと、「Phase の順序に従う」など現状に合わない規則が残る
- 原則は判断の根拠として今も参照されるので、現在の仕様書に移して生かす

## Alternatives Considered

### `design/REQUIREMENTS.md` に改名して残す
**Pros** 参照の書き換えが機械的で済む
**Rejected because:** 利用者（lunaInsidious）の判断。実装計画を含む初期文書を現行文書として残さない
