# ADR-0025: メトリクス定義の日本語版をコードに持たせ、日本語の定義ページも生成する

- **Status:** Accepted
- **Date:** 2026-09-29
- **Deciders:** lunaInsidious, Claude
- **Tags:** docs, metrics, i18n

## Context

### Problem

利用者向けドキュメントは英語と日本語の 2 言語（ADR-0023）だが、メトリクス定義ページはコードの英語の定義から生成しているため英語しかない。

## Decision

- `MetricDefinition` に `ja` フィールド（名前、説明、定義、入力、計算方法、制約の日本語）を追加し、英語の定義のすぐ隣に書く
- 単位・スコープ・参考文献・数式は言語に依らないので 1 つだけ持つ
- 英語の `docs/metrics/` と同じ仕組みで日本語の `docs/ja/metrics/` を生成する。同期は既存の `tests/docs.rs` で検査する
- 英語に値がある欄の日本語が空ならテストを失敗させる（訳漏れの防止）
- `srcmetrics metrics` の JSON 出力と `GET /api/metrics` には `ja` が追加される（フィールドの追加のみで、既存のフィールドは変わらない）。CLI の Markdown 出力は英語のまま

### Rationale

- 定義を変えるとき、英語と日本語が同じ場所に並んでいるので、片方だけ直す事故が起きにくい
- 生成とテストの仕組みを英語版と共有でき、手で書いた翻訳ページが古くなる問題が起きない

## Alternatives Considered

### サイト側に日本語の定義ページを手で書く
**Rejected because:** 定義の変更が日本語版に反映されず、食い違う

### 翻訳を id をキーにした別の表（別ファイル）に持つ
**Pros** 既存の定義の構造を変えずに済む
**Cons** 英語を直したときに日本語が目に入らず、古い訳が残りやすい
**Rejected because:** 英語と並べて置く方が食い違いを防げる
